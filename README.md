# Очистка и унификация данных по ДТП (2020–2024)

## Обзор проекта
Данный этап включает в себя сборку единого каркаса данных из 5 ежегодных выгрузок. Результатом являются три реляционные таблицы, готовые к загрузке в PostgreSQL или ClickHouse.

## Структура данных
На выходе сформированы три основные сущности:

1. **fact_dtp**: Основная таблица происшествий.
   - Ключ: `dtp_id`.
   - Содержит: Время, географию (координаты, адреса), погодные условия и общие последствия (кол-во раненых/погибших).
2. **fact_participant**: Данные об участниках.
   - Ключ: `participant_id`.
   - Связь: `dtp_id` (N:1 к fact_dtp), `vl_id` (N:1 к fact_vehicle).
   - Содержит: Роль участника, возраст, нарушения ПДД, степень тяжести последствий.
3. **fact_vehicle**: Данные о транспортных средствах.
   - Ключ: `vehicle_id`.
   - Связь: `dtp_id` (N:1 к fact_dtp).
   - Содержит: Марку/модель, год выпуска, тип собственности, VIN и описание повреждений.

## Качество данных и аномалии
По результатам первичного аудита выявлены следующие особенности:

### 1. Полнота (Missing Values)
* **География**: Поля `road_name` и `road_loc` имеют ~35 000 пропусков. Это критично для пространственного анализа. Вероятно, данные отсутствуют для происшествий внутри жилых зон или на неразмеченных участках.
* **Технические поля**: Поле `scheme_code` отсутствует в 24 500+ записях.
* **Адреса**: В 8 записях полностью отсутствуют `district_name` и `place_full_path`.

### 2. Целостность (Integrity)
* **Referential Integrity**: 100%. В системе отсутствуют "висячие" записи (участники или ТС без родительской записи ДТП).
* **Дубликаты**: Полные дубликаты строк отсутствуют.

### 3. Логические проверки
* Диапазон дат соответствует ТЗ (2020–2024).
* Возрастные аномалии (младше 0 или старше 110 лет) не зафиксированы / отфильтрованы.

## Инструкция по загрузке
Данные подготовлены в формате `.csv` (разделитель — запятая, кодировка UTF-8). 
Колонки унифицированы:
- Имена приведены к `snake_case`.
- Кириллица в названиях полей полностью устранена.
- Типы данных подготовлены для автоматического распознавания (Numeric, DateTime, String).

## 🏗 Структура и описание таблиц

### 1. Таблица `fact_dtp` (События)
*Основная таблица с информацией о происшествиях.*

| Категория | Поле | Описание |
| :--- | :--- | :--- |
| **Ключи** | `dtp_id` | Уникальный ID происшествия (Primary Key) |
| **Время** | `moment_date`, `moment_time` | Дата и точное время ДТП |
| **Тип** | `type_code`, `type_name` | Код и название вида ДТП (напр., столкновение) |
| **География** | `place_latitude`, `place_longitude` | Гео-координаты (WGS84) |
| | `place_full_path` | Полный адресный путь (Регион -> Район) |
| | `district_name`, `district_id` | Название и ID административного округа |
| | `road_name`, `street_name` | Улица или трасса |
| **Условия** | `light_type_code` | Освещенность на месте |
| | `meteo_clouds` | Погодные условия |
| **Итоги** | `dead_count`, `injured_count` | Кол-во погибших и раненых (всего) |
| | `vehicles_count` | Кол-во участвовавших ТС |

### 2. Таблица `fact_participant` (Участники)
*Информация о людях (водители, пешеходы, пассажиры).*

| Поле | Описание |
| :--- | :--- |
| `participant_id` | Уникальный ID участника |
| `dtp_id` | Ссылка на таблицу ДТП (Foreign Key) |
| `vl_id` | Ссылка на транспортное средство (Foreign Key) |
| `person_age` | Возраст (полных лет) |
| `part_type_code` | Категория (Водитель / Пешеход / Пассажир) |
| `hv_type_code` | Тяжесть последствий для здоровья |
| `main_pdd_derangements` | Список нарушений ПДД |

### 3. Таблица `fact_vehicle` (Транспорт)
*Технические данные об автомобилях.*

| Поле | Описание |
| :--- | :--- |
| `vehicle_id` | Уникальный ID ТС (Primary Key) |
| `dtp_id` | Ссылка на таблицу ДТП (Foreign Key) |
| `mark_name`, `model_name` | Марка и модель ТС |
| `manufacture_year` | Год выпуска автомобиля |
| `vin`, `reg_number` | Идентификаторы (VIN и Госномер) |
| `transport_type_name` | Категория ТС (напр., Такси, Автобус) |
| `damage_description` | Описание повреждений |

**Словарь маппинга полей доступен в файле `data_dictionary.xlsx`.**
