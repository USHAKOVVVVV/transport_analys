# Модуль пространственного обогащения данных о ДТП (Spatial Features)

## Описание проекта
Данный модуль предназначен для пространственного анализа и обогащения исторических данных о дорожно-транспортных происшествиях (ДТП) за период 2022–2024 гг. Модуль решает три ключевые задачи:
1. **Геокодирование и валидация:** Проверка корректности географических координат (широта/долгота) мест аварий.
2. **Дискретизация пространства (H3):** Привязка каждого инцидента к глобальной иерархической сетке Uber H3 на уровнях разрешения `res=8` и `res=9`.
3. **Локальное инфраструктурное обогащение:** Расчет точных расстояний до ключевых объектов (перекрестки/светофоры, пешеходные переходы, остановки общественного транспорта), плотностей POI в радиусах 100 и 300 метров, извлечение скоростных режимов, классов дорог и типов землепользования (Landuse) без обращений к внешним веб-серверам.

## Архитектурные изменения: Переход с Overpass API на локальный GeoPackage
Первоначальная архитектура модуля опиралась на сетевые запросы к серверам OpenStreetMap через библиотеки `OSMnx` и `Overpass API`. Ввиду нестабильности публичных серверов (ошибки `HTTP 406/429`, таймауты соединений), высокой сетевой нагрузки и требований к полной автономности, **архитектура была переведена на локальный высокопроизводительный обсчет**.

В текущей версии модуль один раз считывает локальный файл базы данных OpenStreetMap региона в современном формате **GeoPackage (`.gpkg`)** и выполняет пространственный поиск миллионов объектов в оперативной памяти с использованием оптимизированных деревьев **`scipy.spatial.cKDTree`**. Это обеспечивает:
- **Скорость:** Обсчет всех ~2000 уникальных H3-ячеек занимает менее 30 секунд.
- **Стабильность:** 0% сетевых ошибок, полная независимость от наличия интернета, прокси и VPN.
- **Воспроизводимость:** Гарантия идентичного выполнения скрипта на любой машине в любое время.

##  Спецификация выходных наборов данных

### 1. Таблица уровня ДТП (`feat_spatial_dtp.csv`)
Каждая строка соответствует уникальному инциденту ДТП, обогащенному гео-атрибутами.

| Название признака | Источник | Описание | Ед. измерения |
| :--- | :--- | :--- | :--- |
| `dtp_id` | Входной датасет | Уникальный идентификатор ДТП | Строка / Число |
| `cell_id` / `h3_r8` | Расчетное | Идентификатор H3-ячейки разрешения 8 | Хеш-строка |
| `h3_r9` | Расчетное | Идентификатор H3-ячейки разрешения 9 | Хеш-строка |
| `h3_res` | Константа | Разрешение базового индекса агрегации (`8`) | Целое число |
| `coord_valid` | QA-логика | Флаг валидности координат (попадает ли в рамки региона) | `0` / `1` |
| `distance_to_intersection_m`| OSM (cKDTree) | Точное расстояние до ближайшего светофора/перекрестка | Метры |
| `distance_to_crosswalk_m` | OSM (cKDTree) | Точное расстояние до ближайшего пешеходного перехода | Метры |
| `distance_to_bus_stop_m` | OSM (cKDTree) | Точное расстояние до ближайшей остановки обществ. транспорта | Метры |
| `poi_count_100m` | OSM (Ball query) | Суммарное кол-во POI (светофоры, остановки, переходы) в r=100м | Количество |
| `poi_count_300m` | OSM (Ball query) | Суммарное кол-во POI в r=300м | Количество |
| `crossing_density` | OSM (Ball query) | Плотность пешеходных переходов в радиусе 300 метров | Количество |
| `stop_density` | OSM (Ball query) | Плотность остановок транспорта в радиусе 300 метров | Количество |
| `speed_limit` | OSM (Nearest) | Установленный лимит скорости на ближайшем сегменте дороги | км/ч |
| `road_class` | OSM (Nearest) | Классификация ближайшей дороги (`residential`, `primary`...) | Строка (Категория) |
| `landuse_type` | OSM (Spatial) | Тип преобладающей застройки/землепользования в r=300м | Строка (Категория) |

*Примечание: Таблица также включает в себя сохраненные базовые геометрические параметры дороги, распарсенные из текстовых протоколов (например, `traffic_lane_amount`, `lane_width_m`, `has_traffic_light`, `has_crosswalk` и др.).*

### 2. Таблица уровня пространственных ячеек (`agg_cell_space.csv`)
Каждая строка — уникальная пространственная ячейка H3 разрешения 8. Позволяет оценивать аварийность и инфраструктурный профиль конкретных локаций.

- **`cell_id`**: Уникальный хэш ячейки H3 (служит ключом связи с таблицей ДТП).
- **`h3_res`**: Разрешение сетки (зафиксировано на `8`).
- **`dtp_count`**: Суммарное количество аварий, произошедших внутри данной ячейки за весь период.
- **Инфраструктурные метрики** (`distance_to_...`, `poi_count_...`, `crossing_density`, `stop_density`, `speed_limit`): Среднее арифметическое значение характеристик для центра ячейки.
- **Текстовые профили аварийности** (`has_traffic_light`, `has_crosswalk`, `is_intersection` и др.): Среднее значение (доля инцидентов в ячейке, обладавших данным признаком в протоколе).
- **`road_class` / `landuse_type`**: Доминирующий (наиболее часто встречающийся — функция `mode()`) класс дороги и тип землепользования для ДТП, произошедших внутри ячейки.
